# Fusion — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Donner son effet à la touche `m` : contrôles avant fusion, fenêtre de confirmation qui ne propose que les méthodes autorisées par le dépôt, appel de la mutation GraphQL, et rafraîchissement de la liste après une fusion réussie.

**Architecture:** `MergeMethod` descend de `config` vers `model`, où `github` et `app` peuvent tous deux le voir sans violer le sens des dépendances. `github` gagne `merge_pull_request`, qui récupère l'identifiant GraphQL si on ne le lui donne pas, puis envoie la mutation : l'enchaînement est un détail réseau, il reste chez `github`. `app` porte un champ `merge: Option<MergeDialog>` ; tant qu'il est plein, il capte tout le clavier et bloque le rafraîchissement automatique. `app/render.rs` compose la fenêtre sous forme d'un `MergeRender` — un titre et des lignes déjà écrites — et `ui/merge.rs` ne fait que centrer, encadrer et dessiner.

**Tech Stack:** Rust édition 2021, `ratatui` 0.30, `crossterm` 0.29, `chrono`, `reqwest`, `serde_json`. Aucune nouvelle dépendance.

**Spec:** `docs/specs/04-fusion.md` (contexte transverse : `docs/specs/00-fondations.md` pour les règles de dépendance et les réglages, `docs/specs/01-modele-et-donnees.md` pour `RepoMergeRules`, `PrDetail::node_id` et la mutation, `docs/specs/03-affichage-et-navigation.md` pour l'état de `App`, le clavier et le blocage du `Tick`)

## Décisions prises en écrivant ce plan

Elles sortent du texte de la spec. La tâche 5 les reporte dans les specs concernées, comme l'exige l'ordre de vérité du `CLAUDE.md`.

1. **`MergeMethod` déménage de `config` vers `model`.** `github` a besoin du type pour la mutation et `app` pour la fenêtre. Le laisser dans `config` forcerait `github` à dépendre de `config`, ce que la spec 00 interdit. `config` le réexporte (`pub use crate::model::MergeMethod;`) pour que `config::MergeMethod` reste valide.
2. **`RepoMergeRules::allowed()` rend les méthodes autorisées, dans l'ordre de la spec.** Une seule source pour cet ordre, dans `model`, plutôt que trois `if` recopiés.
3. **L'enchaînement « détail puis mutation » est fait par `github`, pas par `app`.** `Command::Merge` porte un `node_id: Option<String>` ; quand il vaut `None`, `merge_pull_request` appelle d'abord `fetch_detail` et prend l'identifiant de sa réponse. Faire l'enchaînement dans `app` demanderait un état intermédiaire « détail demandé en vue d'une fusion » et deux allers-retours dans la boucle d'événements, pour un résultat identique à l'écran. Conséquence assumée : le détail ainsi récupéré n'entre pas dans le cache de `app`. Rien de la spec ne l'exige, et le rafraîchissement qui suit la fusion réussie le rendrait périmé.
4. **Aucun compteur de génération pour la fusion.** Une seule fusion peut être en vol : tant que la fenêtre est en `Submitting`, aucune touche ne relance quoi que ce soit. `Event::MergeFinished` est simplement ignoré si la clé ne correspond pas à la fenêtre ouverte.
5. **`Ctrl-C` reste armée même fenêtre ouverte.** La spec dit que la fenêtre capte tout le clavier et que « aucune autre touche n'agit ». Cela vaut pour les touches de l'application, pas pour l'interruption : le mode brut a désarmé `Ctrl-C`, et c'est `owl` qui doit l'honorer, sans quoi la seule sortie serait de tuer le terminal. `q` en revanche ne quitte pas tant que la fenêtre est ouverte.
6. **En `Submitting`, aucune touche n'agit, `Échap` comprise.** L'appel est parti ; fermer la fenêtre laisserait croire que la fusion est annulée, alors qu'elle se poursuit.
7. **`App` gagne un champ `notice: Option<String>`, distinct de `error`.** `error` porte les messages de GitHub et se vide à la première réponse réussie. Les motifs de refus de `m` et le « org/dépôt #142 fusionnée » ne sont pas des erreurs de GitHub et ne doivent pas être effacés par le rafraîchissement qui suit immédiatement la fusion. La notice s'efface au premier appui sur une touche, fenêtre fermée.
8. **La barre d'état affiche une aide propre à la fenêtre** : « ↑↓ choisir · Entrée confirmer · Échap annuler ». Laisser « q quitter » pendant que `q` ne fait rien serait un mensonge à l'écran.
9. **La fenêtre ne porte pas de curseur en surbrillance, seulement le chevron `>` de la maquette.** Un seul mécanisme de sélection, celui que la spec dessine.
10. **`MergeRender` est un titre et des lignes déjà écrites**, pas une structure de champs. Toute la composition — le chevron, les libellés, la phrase « imposé par le dépôt », le message d'attente — est décidée dans `app/render.rs`. `ui/merge.rs` calcule la taille, centre, efface le fond et dessine.
11. **Deux libellés par méthode.** La liste utilise la forme longue capitalisée (« Écraser les commits (squash) ») que la maquette montre ; la ligne à méthode unique utilise la forme courte en minuscules (« Méthode : écraser les commits (imposé par le dépôt) ») que la spec cite mot pour mot.
12. **Un `Tick` reçu fenêtre ouverte ne fait rien du tout**, il n'est pas mis en attente. Le minuteur suivant s'en chargera. La spec 03 le décrivait déjà ; c'est ici qu'il est câblé.

```rust
/// Méthode de fusion. Le vocabulaire de GitHub — `SQUASH`, `REBASE`, `MERGE` —
/// reste chez `github` ; ici, seule la notion métier.
///
/// Ce type vit dans `model` et non dans `config` parce que `github` en a
/// besoin pour la mutation : le sens des dépendances interdit à `github` de
/// connaître les réglages.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum MergeMethod {
    Squash,
    Rebase,
    Merge,
}

impl RepoMergeRules {
    /// Méthodes autorisées par le dépôt, dans l'ordre imposé par la spec :
    /// écrasement, rebasage, commit de fusion. C'est aussi l'ordre de la
    /// fenêtre de confirmation, et celui du repli quand la méthode préférée
    /// n'est pas autorisée.
    pub fn allowed(&self) -> Vec<MergeMethod> {
        let mut methodes = Vec::new();
        if self.squash {
            methodes.push(MergeMethod::Squash);
        }
        if self.rebase {
            methodes.push(MergeMethod::Rebase);
        }
        if self.merge {
            methodes.push(MergeMethod::Merge);
        }
        methodes
    }
}
```

```rust
    /// Fusionne une pull request avec la méthode donnée.
    ///
    /// L'identifiant GraphQL n'est pas dans la requête de liste. Quand
    /// l'appelant ne l'a pas — la vue détail n'a jamais été ouverte — il est
    /// récupéré ici par la requête de détail, puis la mutation enchaîne.
    /// L'enchaînement reste du réseau, donc il reste ici : `app` ne fait pas
    /// d'appel et n'a pas à connaître ce détour.
    ///
    /// Rien n'est rendu en cas de succès : `owl` ne lit pas la réponse de la
    /// mutation, il relance une requête de liste.
    pub async fn merge_pull_request(
        &self,
        summary: &PrSummary,
        node_id: Option<String>,
        method: MergeMethod,
    ) -> Result<(), GithubError> {
        let identifiant = match node_id {
            Some(valeur) => valeur,
            None => self.fetch_detail(summary).await?.node_id,
        };
        let variables = json!({ "id": identifiant, "method": methode_graphql(method) });
        // La réponse n'est pas modélisée : seule compte la distinction entre
        // succès et erreur, que `execute` a déjà faite.
        let _: serde_json::Value = self.execute(queries::MERGE, variables).await?;
        Ok(())
    }
```

```rust
    /// Ce que la touche demande à la fenêtre.
    fn handle_key_merge(&mut self, touche: Key) -> Vec<Command> {
        /// Décision prise pendant l'emprunt de la fenêtre, appliquée après.
        enum Suite {
            Rien,
            Fermer,
            Confirmer,
        }

        let Some(fenetre) = self.merge.as_mut() else {
            return Vec::new();
        };

        let suite = match (&fenetre.state, touche) {
            (MergeDialogState::Choosing, Key::Up) => {
                // La sélection ne boucle pas, comme celle de la liste.
                fenetre.selected = fenetre.selected.saturating_sub(1);
                Suite::Rien
            }
            (MergeDialogState::Choosing, Key::Down) => {
                if fenetre.selected + 1 < fenetre.methods.len() {
                    fenetre.selected += 1;
                }
                Suite::Rien
            }
            (MergeDialogState::Choosing | MergeDialogState::Failed(_), Key::Esc) => Suite::Fermer,
            (MergeDialogState::Choosing | MergeDialogState::Failed(_), Key::Enter) => {
                Suite::Confirmer
            }
            // `Submitting` n'accepte rien : l'appel est parti, et fermer la
            // fenêtre laisserait croire que la fusion est annulée.
            _ => Suite::Rien,
        };

        match suite {
            Suite::Rien => Vec::new(),
            Suite::Fermer => {
                self.merge = None;
                Vec::new()
            }
            // La confirmation est câblée à la tâche suivante.
            Suite::Confirmer => Vec::new(),
        }
    }
```

```rust
/// La fenêtre de fusion, prête à dessiner : un titre de cadre et des lignes
/// déjà écrites, chevron de sélection compris. `ui` ne compose rien.
#[derive(Debug, Clone, PartialEq)]
pub struct MergeRender {
    pub title: String,
    pub lines: Vec<String>,
}

const TITRE_FUSION: &str = " Fusionner ";
const AIDE_CHOIX: &str = "Entrée pour confirmer · Échap pour annuler";
const AIDE_ECHEC: &str = "Entrée pour réessayer · Échap pour fermer";
const FUSION_EN_COURS: &str = "Fusion en cours…";

/// Libellé d'une méthode dans la liste de choix.
fn libelle(methode: MergeMethod) -> &'static str {
    match methode {
        MergeMethod::Squash => "Écraser les commits (squash)",
        MergeMethod::Rebase => "Rebaser (rebase)",
        MergeMethod::Merge => "Créer un commit de fusion (merge)",
    }
}

/// Libellé d'une méthode au fil d'une phrase, sans capitale ni parenthèse.
fn libelle_court(methode: MergeMethod) -> &'static str {
    match methode {
        MergeMethod::Squash => "écraser les commits",
        MergeMethod::Rebase => "rebaser",
        MergeMethod::Merge => "créer un commit de fusion",
    }
}

impl App {
    /// Compose la fenêtre de fusion, s'il y en a une.
    ///
    /// La largeur n'entre pas ici : la fenêtre s'ajuste à son contenu, et le
    /// message d'erreur de GitHub n'est jamais tronqué.
    pub fn merge_render(&self) -> Option<MergeRender> {
        let fenetre = self.merge.as_ref()?;

        let mut lignes = vec![
            format!("{} #{}", fenetre.key.repo, fenetre.key.number),
            fenetre.title.clone(),
            String::new(),
        ];

        match &fenetre.state {
            MergeDialogState::Choosing => {
                // Une seule méthode autorisée : rien à choisir, on le dit.
                if let [seule] = fenetre.methods.as_slice() {
                    lignes.push(format!(
                        "Méthode : {} (imposé par le dépôt)",
                        libelle_court(*seule)
                    ));
                } else {
                    lignes.push("Méthode :".to_string());
                    for (indice, methode) in fenetre.methods.iter().enumerate() {
                        let chevron = if indice == fenetre.selected { ">" } else { " " };
                        lignes.push(format!("  {chevron} {}", libelle(*methode)));
                    }
                }
                lignes.push(String::new());
                lignes.push(AIDE_CHOIX.to_string());
            }
            MergeDialogState::Submitting => {
                if let Some(methode) = fenetre.method() {
                    lignes.push(format!("Méthode : {}", libelle_court(methode)));
                }
                lignes.push(String::new());
                lignes.push(FUSION_EN_COURS.to_string());
            }
            MergeDialogState::Failed(message) => {
                lignes.push(message.clone());
                lignes.push(String::new());
                lignes.push(AIDE_ECHEC.to_string());
            }
        }

        Some(MergeRender {
            title: TITRE_FUSION.to_string(),
            lines: lignes,
        })
    }
}
```

```rust
//! Dessin de la fenêtre de confirmation de fusion.
//!
//! Aucune décision : les lignes sont composées par `app`. Ici, seulement la
//! taille, le centrage, l'effacement du fond et le cadre.

use ratatui::layout::Rect;
use ratatui::widgets::{Block, Borders, Clear, Paragraph};
use ratatui::Frame;

use crate::app::MergeRender;

/// Marge intérieure de chaque côté, en plus des deux colonnes de bordure.
const MARGE: u16 = 2;

pub fn draw(frame: &mut Frame, area: Rect, rendu: &MergeRender) {
    let contenu = rendu
        .lines
        .iter()
        .map(|ligne| ligne.chars().count())
        .max()
        .unwrap_or(0);
    let contenu = contenu.max(rendu.title.chars().count());

    // Deux colonnes de bordure, deux marges de chaque côté. La fenêtre ne
    // dépasse jamais l'écran, même si un message de GitHub est très long.
    let largeur = u16::try_from(contenu + 2 + 2 * MARGE as usize)
        .unwrap_or(u16::MAX)
        .min(area.width);
    let hauteur = u16::try_from(rendu.lines.len() + 2)
        .unwrap_or(u16::MAX)
        .min(area.height);

    let zone = Rect {
        x: area.x + (area.width.saturating_sub(largeur)) / 2,
        y: area.y + (area.height.saturating_sub(hauteur)) / 2,
        width: largeur,
        height: hauteur,
    };

    // `Clear` d'abord : sans lui, la liste resterait visible sous la fenêtre.
    frame.render_widget(Clear, zone);

    let cadre = Block::default()
        .borders(Borders::ALL)
        .title(rendu.title.clone());
    let interieur = cadre.inner(zone);
    frame.render_widget(cadre, zone);

    let texte = rendu.lines.join("\n");
    frame.render_widget(
        Paragraph::new(texte),
        Rect {
            x: interieur.x + MARGE.min(interieur.width),
            y: interieur.y,
            width: interieur.width.saturating_sub(2 * MARGE),
            height: interieur.height,
        },
    );
}
```
